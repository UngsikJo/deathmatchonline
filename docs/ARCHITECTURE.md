# 개발 기반 구조

> 4종 캐릭터 확장 검수 중: 현재 코드는 단일 임시 스킬 구성을 사용합니다. 주먹·검·활·마법의 선택·스킬 차이를 반영할 구조는 아래 확장 계획과 [캐릭터 기획안](CHARACTERS.md)을 승인한 뒤 구현합니다.

## 데이터 흐름

브라우저가 `duel` 방에 참가하면 서버가 닉네임과 개발 ID 또는 Supabase 토큰을 검증합니다. 계정의 동시 참가를 잠근 뒤 게임 렌더러의 `ready` 메시지를 기다립니다. 두 명이 준비되면 3초 카운트다운을 거쳐 전투를 시작합니다.

브라우저는 입력 순번·이동 축·스킬만 전송합니다. 서버는 형식과 속도를 검증하고 `Simulation`을 30틱/초로 실행합니다. 전체 공개 스냅샷을 20회/초 메시지로 전송합니다. 아직 Colyseus Schema 델타 압축을 사용하지 않습니다. 적은 플레이어 수에서 규칙을 검증하기 위한 출발점이며, 실제 메시지 크기는 이후 측정해 최적화합니다.

게임 상태에는 서버의 시뮬레이션 시간이 들어 있습니다. 클라이언트는 마지막 수신 시각 이후 최대 150ms까지만 시간을 추정하여 쿨다운·예고 표시가 멈춘 연결에서 무한히 앞서지 않게 합니다.

## 책임 경계

- `shared/rules.ts`: 수치, 스킬 정의, 충돌·이동 계산. 클라이언트가 사용하더라도 서버 판정 권한이 넘어가지는 않습니다.
- `shared/protocol.ts`: 메시지 타입, 런타임 입력 검증, 연승 전이.
- `shared/simulation.ts`: 이동·시전·명중·체력·시간·승패. 네트워크와 분리하여 테스트합니다.
- `DuelRoom`: 방 수명, 준비, 입력 제한, 누적 재접속 예산, 정산 호출.
- `DevStore`: 프로세스 메모리의 테스트 전적. 서버 종료 시 사라집니다.
- `game/session.ts`: 연결, 재접속 토큰, 스냅샷·통계를 React와 Phaser에 공유합니다.
- `ArenaScene`: 입력 수집, 캐릭터·범위·투사체 렌더링. 체력이나 승패를 직접 결정하지 않습니다.

## 현재 의도적인 제한

첫 구현은 단일 프로세스입니다. 참가 잠금·정산 중복 방지도 메모리에 있으므로 여러 서버 인스턴스로 늘리면 안전하지 않습니다. 인증에 Supabase를 연결해도 전적이 영구 저장되지는 않습니다.

내 캐릭터는 입력에 따라 먼저 이동하며 서버 위치로 연속 보정합니다. 입력 이력을 마지막 처리 순번까지 재실행하는 방식은 아직 아닙니다. 상대는 보간합니다. 높은 지연에서 조작감이 충분한지는 검증이 필요합니다.

렌더링 모양과 실제 충돌 크기는 다릅니다. 플레이어 몸은 반지름 16, 맵은 공통 사각형 데이터입니다. 현재 Tiled 원본은 없으며 아트 반입 단계에서 공유 맵 데이터 생성기를 추가합니다. 돌진은 각 틱과 180ms 동작 구간이 겹치는 시간만큼 이동해 틱 경계에서도 거리를 보존합니다.

경기가 끝나면 결과를 한 번 정산하고 방을 잠급니다. 사용자는 방을 떠나 다음 상대를 찾습니다. 결과 방은 최대 60초 뒤 정리됩니다. 단절된 사용자가 결과 완료 후 복귀하지 못할 수도 있으며, 이를 해결하려면 영구 경기 기록 조회가 필요합니다.

## 영구 저장 도입 시 변경점

1. 방 참가 전 DB 경기·참가 레코드와 잠금을 생성합니다.
2. 경기 ID와 두 참가자의 결과를 서버 전용 PostgreSQL 함수 하나에서 정산합니다.
3. 해당 함수는 경기 상태 조건과 행 잠금으로 중복 정산을 막습니다. 클라이언트 호출은 허용하지 않습니다.
4. 정산 실패 시 결과 화면에 저장 중 상태를 표시하고 다음 매칭을 차단합니다.
5. 서버 장애로 남은 진행 경기·참가 잠금에 유효 기간을 두고 복구 작업을 작성합니다.
6. DB 결과 조회를 추가한 뒤 생산 환경 실행 제한을 재검토합니다.

SQL 함수·RLS는 실제 Supabase 테스트 프로젝트에서 두 사용자 권한과 중복 정산을 검증한 후 연결해야 합니다.

## 4종 캐릭터 확장 계획 — 검수 초안

- 전역 `SKILLS` 하나를 모든 플레이어가 쓰는 현재 구조를 캐릭터 정의별 `skills` 조회로 변경합니다. 공통 키는 유지하며 실제 스킬은 고정된 캐릭터 ID로 결정합니다.
- 서버는 대기 전 `characterId`를 검증·확정하고 준비·전투·정산·재접속 동안 고정합니다. 투사체·효과·기록에도 캐릭터와 스킬 ID를 연결합니다.
- 현재 투사체의 `S | W` 제한을 일반화해야 합니다. 새 배치에서는 활형 D/F/Q/W/E/R, 마법형 D, 검형 E 등 여러 슬롯에서 투사체를 사용합니다. A는 유지 방어이므로 투사체를 발사하지 않습니다.
- 캐릭터별로 전투 전체를 복제하지 않고 이동·공격 형상·투사체·방어·상태·다단 공격을 데이터와 공통 계산으로 조합합니다.
- 캐릭터 선택과 HUD는 F08, 전투 정의는 F04, 매칭 잠금은 F05, 경기별 캐릭터 기록은 F06, 복원은 F07, 시각·음향은 F10과 연결합니다.
- 게임 코드의 ‘동일 캐릭터·동일 능력치’ 안내와 단일 스킬 이름 표시는 선택 캐릭터 기준으로 바꿀 대상입니다. 이번 검수 문서 작업에서는 런타임 화면 문구나 로직을 수정하지 않습니다.
- 초기 기획의 개발 기간은 단일 캐릭터 기준이므로 승인 후 4종 범위로 다시 산정합니다.

## 공통 조작·게이지 변경 계획 — 검수 초안

- 새 배치는 A 웅크려 막기·S 대시·D 기본 공격·F 쓰러진 상대 추가 공격·Q/W/E 기본 스킬 1/2/3·R 궁극기입니다. [상세 계약](COMBAT_CONTROLS.md)을 기준으로 구현합니다.
- 현재의 단발 `skill` 메시지에 A를 남기지 않고 `guardHeld` 유지·해제 상태를 추가합니다. 방어 진입·해제·방향 고정·입력 만료를 서버가 결정합니다.
- R의 발동 조건은 일반 쿨다운이 아니라 `ultimateCharge` 0~10,000 정수의 100% 조건입니다. 유효 요청의 검사·0으로 소비·시전 시작을 한 입력 처리에서 수행합니다.
- 피해 처리는 충돌 수집 → 무효·방어 감소·올림·보호막·남은 HP 제한 → 실제 피해 확정 → 피해 사건별 게이지 충전 → 승패 순서로 구분합니다.
- 초기 계수안은 일반 HP 피해 1당 공격자 200단위·피격자 100단위입니다. R 공격자는 자기 R로 충전하지 않고, 피격자는 실제 받은 HP 피해로 충전합니다.
- 실제 피해 이벤트에 유일 ID·시전자·피격자·캐릭터/기술 ID·궁극기 여부를 연결합니다. 스냅샷 재수신이나 입력 재시도로 같은 피해를 재충전하지 않습니다.
- `PlayerSnapshot`에 방어 상태·방향·게이지를 포함하고 양쪽 HUD에 표시합니다. 준비 상태는 서버 게이지와 현재 행동 가능 상태에서 계산합니다.
- 게이지는 같은 경기 재접속 시 복원하고 새 경기마다 0%입니다. 연승·영구 통계와 별개이며 매 틱 DB에 저장하지 않습니다.
- 현재 코드의 D 대시·F 보호막 분기, R 20초 쿨다운, 모든 키를 단발로 처리하는 로더는 승인 후 교체합니다. 이번 문서 작업은 런타임 변경이 아닙니다.

## 다운·F 추가 공격 변경 계획 — 검수 초안

- 사용자 확인으로 F는 살아 있는 다운 상대의 추가 공격입니다. 상태를 `standing`, `downed`, `recovering`으로 나누고, HP 0의 KO·경기 종료를 별도로 처리합니다.
- 공격 정의에 `targetStates`, 다운 유발 여부·시간·정면 방어 가능 조건을 추가합니다. 기본안의 일반 공격은 서 있는 상대, F는 다운 상대만 대상으로 합니다.
- 서버는 틱 시작의 시간 만료·기상을 먼저 처리하고, 충돌·실제 피해·게이지·HP 0·다운 부가 효과의 순서를 명시합니다. 같은 틱의 치명 공격은 기존 동시 판정을 유지합니다.
- 다운 회차 ID, 종료·기상 시각, F 적중 사용 여부, 다운 면역 기한을 서버 상태와 스냅샷에 포함합니다. F가 기록한 대상·회차와 현재 상태를 명중 때 다시 검사합니다.
- 유효 F 1회 적중 시 HP가 남으면 기상으로 전환합니다. 중복 입력·동시 투사체가 같은 다운 회차를 두 번 소비하지 못하게 합니다.
- 다운·기상 중 이동·방어·새 공격을 막고 진행 중 시전·대시를 종료합니다. 이미 소비한 궁극기는 환급하지 않으며 피해로 모인 게이지는 유지합니다.
- F가 실제 HP 피해를 준 경우 일반 충전 계수를 적용합니다. 다운 발생 자체·보호막에 전부 흡수된 타격은 별도 게이지를 만들지 않습니다.
- 같은 경기 재접속 시 남은 다운·기상·면역과 F 회차를 복원하고 새 경기에는 초기화합니다. 타이머는 접속 종료 동안에도 진행합니다.
