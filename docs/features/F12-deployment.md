# F12 — 환경 분리·배포·CI

- 브랜치: `feature/deployment`
- 우선순위: P0, 비공개/공개 베타 진입 조건
- 상태: 로컬 실행·검증 명령과 CI 템플릿만 준비
- 기준: `bfe35d3`, [PRD](../PRD.md) 13~16절, [CI 안내](../CI.md)
- 선행 기능: F01, F06~F11, [기능 목록](README.md)

## 목표와 현재 상태

사용자가 실제 웹 주소에서 가입·매칭·전투·기록 조회를 하고, 개발자 한 명이 배포·점검·복구할 수 있는 환경을 만듭니다.

현재 웹·서버는 로컬 주소에 바인딩하고 production 실행을 거절합니다. 정적 웹·Node 서버 빌드는 가능하지만 배포 계정·DB 영구 정산·운영 환경 연결은 없습니다. Git 인증의 워크플로 수정 권한이 없어 CI는 `docs/ci.yml.example` 템플릿으로 보관돼 있습니다.

## 환경과 배포 범위

| 환경     | 용도·필수 조건                                                   |
| -------- | ---------------------------------------------------------------- |
| 로컬     | 기존 게스트 개발 모드, `npm run dev`                             |
| 스테이징 | 운영과 분리된 DB·메일·주소, 인증된 테스트 계정과 실제 배포 검증  |
| 운영     | 인증 전용 참가, 영구 정산, 허용 출처·비밀 키·상태 점검·오류 추적 |

1. 웹은 `apps/web/dist`, 게임 서버는 공통 패키지와 서버 빌드 결과를 사용합니다. 루트 `npm ci`·`npm run build` 후 서버 workspace 실행 경로를 검증합니다.
2. PRD의 정적 웹 호스팅·상시 실행 Node 서버·Supabase 분리 구성을 기준으로 합니다. 서버 지역은 실제 한국 회선 RTT·비용 측정 후 확정합니다.
3. 웹 HTTPS와 게임 WSS, 인증 복귀 URL, CORS·허용 출처를 같은 환경 주소로 맞춥니다. 운영 DB 자격 증명은 서버 환경에만 설정합니다.
4. 필수 인증·DB·공개 주소 설정이 없으면 운영 서버 시작 또는 매칭 준비 상태가 실패해야 합니다. DB 장애를 게스트·메모리 저장 모드로 자동 전환하지 않습니다.
5. production 시작 제한은 F06 영구 정산·F07 복구·F11 보호 검증과 실제 스테이징 수용 기준이 끝난 뒤 교체합니다. 단순 삭제로 활성화하지 않습니다.
6. MVP는 단일 게임 서버 프로세스입니다. 수평 확장·다중 지역 라우팅은 별도 범위입니다.

## CI·점검·복구

- 워크플로 수정 권한이 준비되면 기존 템플릿을 `.github/workflows/ci.yml`로 활성화합니다. 이 명세 브랜치 자체는 워크플로 파일을 추가하지 않습니다.
- CI는 Node 24에서 설치·포맷·타입·단위 테스트·빌드·SDK 통합 검증을 실행하고, 실계정·DB 테스트는 별도 스테이징 자격 증명과 격리된 데이터로 실행합니다.
- 배포 전 신규 매칭을 중지하고 준비 중인 사용자를 정리합니다. 진행 경기는 종료·정산 완료를 기다린 뒤 프로세스를 종료합니다. 강제 종료는 F07 복구 작업으로 처리합니다.
- `/health`는 프로세스 생존, 추가 준비 상태 경로는 DB·인증 설정과 매칭 가능 여부를 구분합니다. 비밀 값이나 내부 상세 오류를 반환하지 않습니다.
- 이전 애플리케이션 버전으로 되돌릴 수 있도록 빌드·규칙 버전·배포 식별자를 기록합니다. DB migration은 복구 계획 없이 자동 역실행하지 않습니다.
- 정산 실패·무효 비율·틱 지연·트래픽·월 비용을 관찰하고, 증설은 부하 측정 후 결정합니다.

## 영향 파일과 사용자 준비

- `apps/web/vite.config.ts`, `apps/game-server/src/config.ts`, `server.ts`, `index.ts`.
- 루트 실행 명령, 배포 설정, 환경 예시, health/readiness 모듈.
- 권한 확보 후 `.github/workflows/`, `docs/CI.md`, `docs/SUPABASE.md`, 배포·복구 문서.
- 사용자 준비: 호스팅·Supabase·SMTP 계정, 도메인/DNS 접근, 예산, 워크플로 수정 권한. 비밀 토큰을 저장소나 채팅에 넣지 않습니다.
