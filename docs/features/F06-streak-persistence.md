## 목표와 현재 상태

서버 재시작·새 브라우저 로그인 뒤에도 확정된 현재·최고 연승과 승패 기록을 조회합니다. 같은 경기 정산의 재시도나 중복 요청으로 승수가 늘어나지 않아야 합니다.

현재 `DevStore`는 메모리 Map과 Set으로 통계·참가·한 번 정산을 관리합니다. DB 스키마·RLS 초안은 있으나 적용·검증·서버 연결은 없습니다. 현재 `roomId`와 사용자 세션 ID를 영구 식별자로 그대로 사용하면 안 됩니다.

## 결과별 불변 규칙

| 결과                              | 현재 연승 | 최고 연승        | 누적 기록  |
| --------------------------------- | --------- | ---------------- | ---------- |
| 승리                              | +1        | 새 기록이면 갱신 | 승 +1      |
| 패배·기권·단독 이탈 패배          | 0         | 보존             | 패 +1      |
| 무승부                            | 양쪽 0    | 보존             | 양쪽 무 +1 |
| 경기 사이 휴식·로그아웃·매칭 취소 | 보존      | 보존             | 변화 없음  |
| 시작 전 취소·서버 장애 무효       | 보존      | 보존             | 변화 없음  |

최고 기록을 **처음** 달성한 시각을 저장합니다. 같은 최고값 재달성은 시각을 바꾸지 않습니다. 승패의 결정은 F04·기권 및 연결 규칙은 F07에서 받아, 이 기능은 검증된 단일 결과만 정산합니다.

## 정산 절차와 계약 제안

1. 전투 시작 전에 서버가 DB 경기 UUID, 참가자 계정 ID, 규칙 버전·서버 인스턴스 ID를 저장합니다. 클라이언트 세션 ID는 이 계정 매핑과 구분합니다.
2. 종료 조건이 확정되면 전투 입력을 잠그고 `finalizing` 상태로 바꿉니다. 서버 `Snapshot.phase` 확장이 필요하며 F08과 동시에 적용합니다.
3. 서버 전용 `settle_match` 함수에 경기 UUID·확정 승자·사유·최종 상태를 전달합니다. 브라우저 호출 권한은 주지 않습니다.
4. 경기와 두 통계 행을 일관된 순서로 잠그고, 결과·참가자별 outcome·현재/최고 연승·참가 상태를 한 트랜잭션으로 갱신합니다.
5. 같은 경기·같은 결과 재시도는 저장된 정산 영수증을 반환합니다. 같은 경기의 다른 승자·사유 요청은 충돌로 거절하고 기존 결과를 보존합니다.
6. 커밋 성공 후에만 확정 통계와 결과를 전달하고 다음 매칭을 허용합니다. DB 실패 시 같은 UUID로 재시도하며 임의 승수·성공 안내를 보여 주지 않습니다.
7. 종료 이벤트가 유실돼도 본인 최근 경기·경기 UUID 조회로 결과를 복원합니다. 다른 사용자만의 경기 상세는 읽을 수 없습니다.
8. 프로세스가 커밋 전에 사라져 복구할 결과가 없으면 F07이 해당 경기를 무효화합니다. 이미 커밋된 결과는 무효화하거나 재계산하지 않습니다.

영수증은 `matchId`, `status`, `winnerUserId`, 사유, `endedAt`, 참가자별 `streakBefore`·`streakAfter`와 통계 버전을 포함하는 안입니다. 클라이언트에는 본인에게 허용된 정보만 전달합니다. 시각은 UTC 저장·한국 시간 표시입니다.

## 데이터와 권한

- `matches`, `match_participants`, `player_stats`, `active_participations`를 연결합니다.
- 새로운 migration에서 정산 함수·함수 실행 권한·결과 조회 정책·필요 제약을 추가합니다. 이미 적용된 migration은 수정하지 않습니다.
- 통계 수정은 서버 경로만 허용합니다. 닉네임 변경·매칭 취소·계정 재로그인으로 현재 연승을 재설정하지 않습니다.
- 계정 삭제 시 본인 통계·프로필은 삭제하고 과거 경기의 사용자 참조는 익명화합니다. 타인의 확정 통계는 그대로 유지하며 F01과 경쟁을 검증합니다.
- 사용자 ERD에서 탈퇴 정책을 미정으로 표시했습니다. 위 익명화는 후속 목표이며, 준비 migration은 기록 손실 방지를 위해 경기 계정 FK를 `RESTRICT`로 보호합니다. 정책 확정·익명화 migration 전에는 경기 기록이 있는 계정을 직접 삭제할 수 없습니다.
- 메모리 저장소는 명시적인 개발 모드에만 남깁니다. DB 장애를 감추려고 자동 전환하지 않습니다.
