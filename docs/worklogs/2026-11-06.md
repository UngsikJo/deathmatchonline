## 10. 검수 초안 수정 — 고정 키 배치·궁극기 게이지

- 사용자 지정에 따라 A 웅크려 막기·S 대시·D 기본 공격·F 아래 공격·Q/W/E 기본 스킬 1/2/3·R 궁극기로 캐릭터 4종을 재배치했습니다.
- F는 우선 현재 바라보는 방향의 하단 공격으로 해석하고 확인 질문을 남겼습니다. 화면 아래 고정 방향인지 여부는 검수 전 확정하지 않습니다.
- [공통 조작·게이지 명세](../COMBAT_CONTROLS.md)에 A 유지·해제·입력 만료, 실제 HP 피해 기반 충전, 100% 준비·사용 시 전부 소비를 정리했습니다.
- 초기 충전 계수는 일반 HP 피해 1당 공격자 2%·피격자 1%라는 제안입니다. 방어·보호막·오버킬·궁극기 자체 피해·중복 사건 처리와 정수 계산 예시를 작성했습니다.
- R 고정 시간 쿨다운을 대체하는 게이지 조건, 같은 경기 재접속 보존·새 경기 0%, 잘못된 요청 거절·중복 소비 방지를 명세했습니다.
- 캐릭터·README·PRD·구조·개발 목록·로컬 UI 명세를 같은 기준으로 수정했습니다. A 공통 동작을 포함한 32개 입력 항목을 모두 다른 고유 스킬이라고 표현하지 않도록 정리했습니다.
- 새 키 배치의 4종별 8개 항목·총 32개, 게이지 계산 예시 7개, 로컬 링크 87개와 문서 구조 검증을 통과했습니다. 포맷·공백 검사를 확인하고 소스·HEAD·스테이징 상태가 바뀌지 않았음을 확인했습니다. 런타임 구현 검증을 수행한 결과는 아닙니다.
- 이전 사용자 검수 조건을 유지합니다. 이번 작업도 게임 코드 변경·커밋·푸시 없이 로컬 초안으로 보관합니다.

## 11. 사용자 답변 반영 — F는 쓰러진 상대 공격

- 사용자가 F의 의미를 ‘쓰러진 상대를 공격’으로 확인했습니다. 이전의 하단 공격 해석을 폐기하고 캐릭터 4종·조작·README·PRD·구조·UI 명세를 수정했습니다.
- HP가 남아 있는 다운과 HP 0의 KO를 분리했습니다. 다운 1초·F 유효 적중 1회 뒤 기상·기상 동작 0.3초·완전히 일어난 뒤 다운 면역 1.5초를 세부 검수안으로 제안했습니다.
- 주먹형 E·검형 Q·활형 E·마법형 Q를 다운 유발 기술로 지정하고 각 F를 파운딩·다운 베기·다운 사격·다운 파동으로 재정의했습니다. 기술 이름·수치는 초안입니다.
- F의 대상·다운 회차·거리·방향·벽을 발동/명중 시 확인하고, 서 있는 상대·KO 대상·만료·기상·중복 회차 타격을 처리하도록 명세했습니다.
- 다운 중 행동 잠금·기상 보호·진행 시전 취소·재접속 복원과 F 실제 HP 피해의 일반 궁극기 충전 처리를 정리했습니다.
- 문서 11개·로컬 링크 85개, 두 상세 명세의 표 열·코드 블록, 캐릭터 4종의 총 32개 입력 항목과 다운 기술·F 대상·R 조건을 확인했습니다. 포맷·공백 검사도 통과했습니다. 게임 소스·HEAD 유지 및 스테이징 없음도 확인했으며 런타임 테스트는 이번 문서 수정에서 실행하지 않았습니다.
- 이번 답변은 F 의미에 대한 확인이며 전체 캐릭터·밸런스 초안의 푸시 승인은 아닙니다. 기존 검수 조건대로 로컬 문서만 수정하고 게임 코드·커밋·푸시는 보류합니다.

## 12. UI/UX 검수 목업 — 무한의 계단 느낌

- 사용자 요청에 따라 무한의 계단의 공식 Google Play와 제작사 제공 대표·플레이·캐릭터 이미지를 조사했습니다. 도트 표현·큰 기록 숫자·명확한 게이지·각진 테두리·큰 주 행동을 이 프로젝트에 맞춰 해석했습니다. 공식 이미지 원본은 임시 확인용으로만 내려받았고 저장소에는 반입하지 않았습니다.
- [UI/UX 디자인 명세](../UI_UX_DESIGN.md)에 레퍼런스 출처, 색·글꼴·레이아웃, 화면별 흐름, 예외 상태와 검수 항목을 정리했습니다. 편집 원본은 `docs/design/deathmatch-arcade-mockup.html`입니다.
- 로비·캐릭터 선택·전투·결과·로그인/가입의 5화면을 연결했습니다. 직접 작성한 캐릭터 4종 도트·무기·경기장을 사용하고, 선택 시 외형·이름·8개 기술 설명을 함께 갱신합니다.
- QWER/ASDF, F 다운 대상 강조, R 100% 준비·사용 후 0%, 기상·재접속 잠금, 기권 확인과 결과 저장 중/실패·재시도를 검수할 수 있습니다. 승리 후 계속 도전·쉬기·기본 해제 자동 매칭과 취소 가능한 카운트다운을 예시로 연결했습니다.
- Chrome에서 5화면과 회원가입 전환을 직접 확인했습니다. 약 960px·510px 창에서 로비·전투·가입 폼을 시각 확인하고, 캐릭터 변경·F 활성화와 적중 후 게이지 갱신·R 100% 및 사용 후 0%·기상/재접속 입력 제한·저장 중 다음 대전 차단·실패 재시도·로비 복귀 뒤 차단 유지·매칭 모달을 확인했습니다. 320px 실제 기기와 게임 서버 연결은 검증하지 않았습니다. 창 크기는 검수 후 복원했습니다.
- JavaScript 구문·HTML 고유 ID·5개 탭 연결·1MB 미만 크기·로컬 문서 링크 95개를 확인했습니다. 포맷·공백 검사도 통과했습니다. 전투 계산·로그인·정산의 런타임 테스트를 대신하는 검증은 아닙니다.
- 목업의 Google Fonts 3종 원본 OFL 1.1을 확인해 [에셋 장부](../ASSET_LICENSES.md)에 기록했습니다. 글꼴 파일은 반입하지 않았고 실제 게임 웹의 시스템 글꼴은 그대로입니다.
- 사용자 요청대로 검수 단계에서 멈춥니다. 게임 소스·의존성·HEAD 변경과 스테이징 없이 목업·명세·일지만 로컬에 보관했습니다. 커밋·푸시·외부 서비스 배포는 하지 않았습니다.

## 13. UI/UX 브랜치 공유 승인과 반영

- 사용자가 초기 목업을 UI/UX 담당 브랜치에 푸시하고 이후 수정하도록 지시했습니다. 대상은 기존 `feature/lobby-ui`이며 별도의 중복 기능 브랜치는 만들지 않습니다.
- 최신 원격 이력을 확인하고 별도 작업 폴더에서 `feature/lobby-ui`를 최신 `main`까지 fast-forward했습니다. 기존 로컬 문서는 백업해 보존했습니다.
- 목업·UI/UX 명세·F08 명세·에셋 장부와 목업이 참조하는 캐릭터·조작·PRD·문서 목록을 함께 정리했습니다. 캐릭터·전투 수치는 참고 초안이며 게임 소스·의존성·DB·배포 설정은 변경하지 않습니다.
- UI 초기안의 공유 승인과 게임 적용 전 상태를 문서에 표시했습니다. 한국어 커밋 메시지 규칙을 적용하며 기능 브랜치의 검증 후 해당 브랜치만 푸시합니다.
- 공유 작업 폴더에서 문서·목업 14개와 로컬 링크 97개, JavaScript 구문·고유 ID·5개 화면 탭·1MB 크기 제한·포맷·공백 검사를 통과했습니다. 게임 소스·의존성·DB·워크플로 변경이 없음을 확인했습니다.
