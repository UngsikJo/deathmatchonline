# F11 — 요청 검증·운영 보호

- 브랜치: `feature/security-operations`
- 우선순위: P0, 공개 베타 전 검증
- 상태: 기본 보호 일부 구현, 통합 운영 검증 미완료
- 기준: `bfe35d3`, [PRD](../PRD.md) 8·12·14절
- 선행 기능: F01, F05, F06, F07, [기능 목록](README.md)

## 목표와 현재 상태

위조 입력·참가 도배·중복 정산·정보 노출을 막고, 한 사람이 오류와 비정상 경기를 조사할 수 있게 합니다. 개별 기능의 기본 권한 검사를 대신하는 단계가 아니라 통합 검증과 운영 수단을 추가하는 단계입니다.

현재 허용 출처 검사, WebSocket 4096byte 제한, 이동 입력 최대 90회/초, 입력 형식·순번·쿨다운 검사, 인증 토큰 검증이 있습니다. `ready`, `sync`, 매칭 HTTP 요청의 제한, 영구 운영 이벤트·지표·부정 경기 조사 흐름은 미완료입니다.

## 필수 보호 규칙

1. 모든 메시지의 형식·필드·길이를 서버에서 검사합니다. 이동·스킬뿐 아니라 준비·동기화·기권·대기열 요청에도 제한을 둡니다.
2. 유효한 계정·방 참가 신원으로 권한을 검사합니다. userId·승자·피해·좌표·연승 값을 클라이언트가 지정해 실제 상태를 바꾸지 못하게 합니다.
3. 인증/계정/매칭 API는 계정과 요청 출처에 맞춰 요청 빈도를 제한하고 `retryAfter`를 제공합니다. 공유 IP의 정상 사용자들을 한 계정처럼 취급하지 않습니다.
4. 제한값·관측 구간·조치·복구 시간을 문서화하고 서버 설정으로 관리합니다. 네트워크 재시도만으로 정상 사용자를 무기한 차단하지 않습니다.
5. 결과 저장은 F06의 경기 ID 기반 정산을 사용하고, DB 통계·경기·달성 시각의 일반 사용자 쓰기 권한을 실제 2계정으로 검증합니다.
6. 허용 출처 목록은 HTTP와 WebSocket에 적용하되 인증을 대체하지 않습니다. 운영 환경에서 토큰 없는 요청은 읽기 공개 경로만 허용합니다.
7. 반복 상대·비정상적으로 빠른 기권·승률·반복 이탈은 조사 이벤트로 남깁니다. 오탐만으로 자동 승수 삭제나 무기한 제재를 시행하지 않습니다.
8. 관리자 경로는 서버에서 별도 권한을 검증합니다. 화면에서 메뉴만 숨기는 방식으로 보호하지 않습니다.

## 로그와 운영 계약 제안

- 구조화 이벤트: 시각, 요청 ID, 경기 ID, 이벤트 종류, 사유 코드, 처리 지연, 익명화한 사용자 식별자.
- 기록 제외: 비밀번호, access/refresh/reconnection token, 전체 인증 헤더, 사용자 이메일, 전체 요청 본문.
- 지표: 활성 경기·대기 인원, 매칭 시간, RTT, 틱 처리 시간, 재접속·무효 비율, 정산 실패·재시도 횟수, 요청 제한 횟수.
- 초기 로그 보관은 7일이라는 운영 초안을 두고 공개 전 실제 보관 기간·권한·삭제 작업을 확정합니다. 플레이어 경기 기록의 보관과 디버그 로그 보관은 구분합니다.
- MVP 운영 수단은 제한된 조회·점검 모드·오류 알림을 우선합니다. 상시 감시 대시보드·복잡한 제재 UI·완전한 DDoS 방어 구현은 범위 밖입니다.
