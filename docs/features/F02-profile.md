# F02 — 닉네임·프로필

- 브랜치: `feature/profile`
- 우선순위: P0
- 상태: 기능 명세 초안, DB 연결 미완료
- 기준: `bfe35d3`, [PRD](../PRD.md) 9·11절
- 선행 기능: F01, [기능 목록](README.md)

## 목표와 현재 상태

같은 계정으로 접속하면 저장한 닉네임과 프로필을 불러옵니다. 닉네임은 다른 계정과 구분 가능하고, 상대에게 이메일을 노출하지 않습니다.

현재 닉네임은 탭의 sessionStorage와 참가 옵션에서 전달합니다. 서버의 형식 검사와 `profiles` 초기 migration 초안은 있으나 DB 프로필 조회·수정, 전역 중복 검사, 기존 계정 backfill은 연결되지 않았습니다. 서버의 Hangul 문자 검사와 화면의 완성형 한글 검사도 통일해야 합니다.

## 범위와 규칙

1. 가입 시 기본 프로필을 생성하고 로비에서 사용자에게 닉네임 설정을 안내합니다. 기존 인증 계정의 프로필 누락도 복구합니다.
2. 닉네임은 앞뒤 공백 제거 후 완성형 한글·영문·숫자·밑줄 2~12자만 허용합니다. 동일한 규칙을 웹·서버·DB에 적용합니다.
3. 영문 대소문자를 무시한 정규화 값에 DB 유일 제약을 둡니다. 동시 변경 경쟁은 최종 DB 결과로 판단합니다.
4. 서버가 검증한 계정 ID로 프로필을 찾고, 공개 대전의 닉네임은 DB 값을 사용합니다. 클라이언트가 다른 이름을 제출해도 덮어쓰지 않습니다.
5. 대기열·준비·전투·정산 중 닉네임 변경은 거절하고 로비로 돌아오도록 안내합니다. 표시 중인 경기 참가자 이름이 중간에 바뀌지 않게 합니다.
6. 공개 프로필은 표시 이름 등 공개 필드만 제공합니다. 인증 이메일·세션·내부 운영 정보는 포함하지 않습니다.
7. 통계 계산·최고 연승 갱신은 F06, 순위 정렬은 F09에서 담당합니다. 아바타 업로드·칭호·친구 기능은 제외합니다.

## 데이터·화면 계약

- `profiles`: `user_id`, `nickname`, `nickname_normalized`, `created_at`. 정규화 값은 DB에서 생성합니다.
- 본인 프로필 조회·닉네임 변경 API 또는 동일한 RLS 권한의 데이터 호출을 추가합니다. 호출자는 닉네임만 변경할 수 있고 `user_id`·생성 시각은 수정할 수 없습니다.
- 화면은 `loading`, `ready`, `editing`, `saving`, `conflict`, `error`를 구분합니다. 실패 시 마지막 확정 값을 유지합니다.
- 오류 식별은 형식 오류·중복·인증 만료·경기 참여 중·프로필 복구 실패로 구분합니다. 테이블 내부 오류를 그대로 표시하지 않습니다.
- F06 연결 전에는 미연결 통계를 실제 0승 확정 기록처럼 표시하지 않습니다.

## 수용 기준

| 조건                                    | 기대 결과                                            |
| --------------------------------------- | ---------------------------------------------------- |
| 같은 계정으로 다른 브라우저 로그인      | 같은 저장 닉네임 조회                                |
| `Hero`가 존재할 때 `hero` 저장          | 중복 거절                                            |
| 두 계정이 동시에 같은 이름 저장         | 한 계정만 성공, 다른 계정은 중복 안내                |
| 1자·13자·HTML·허용하지 않은 자모 입력   | 웹·서버·DB에서 일관되게 거절                         |
| 다른 사용자 ID 또는 생성 시각 수정 시도 | 권한 거절, 실제 값 유지                              |
| 참가 옵션의 닉네임을 조작함             | DB의 확정 닉네임으로 참가                            |
| 기존 계정에 프로필이 없음               | 한 번만 생성·복구, 통계나 다른 프로필 중복 생성 없음 |

## 영향 파일과 준비 사항

- `apps/web/src/App.tsx`, 프로필용 컴포넌트·조회 모듈.
- `apps/game-server/src/services.ts`, 공통 닉네임 검사 모듈.
- `supabase/migrations/202611060001_initial_schema.sql`을 검토하되 적용 후 수정은 새 migration으로 추가.
- 본인/타인 2계정 RLS 테스트와 동시 닉네임 저장 테스트가 필요합니다.
- Supabase 개발 DB가 필요하며 실제 이메일·운영 계정 정보를 테스트 저장소에 넣지 않습니다.
