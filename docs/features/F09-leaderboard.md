# F09 — 최고 연승 순위표

- 브랜치: `feature/leaderboard`
- 우선순위: P0
- 상태: 미구현
- 기준: `bfe35d3`, [PRD](../PRD.md) 5·7절
- 선행 기능: F06, [기능 목록](README.md)

## 목표와 현재 상태

확정된 공개 경기 기록으로 최고 연승 상위 100명과 본인 순위를 보여 줍니다. 클라이언트가 제출한 점수나 아직 정산되지 않은 승리는 순위에 반영하지 않습니다.

현재 로비에 메모리 통계만 있고 순위표 화면·조회 API는 없습니다. 초기 DB 초안에 최고 연승과 달성 시각 인덱스가 있으나 실제 데이터 정산은 F06에서 먼저 연결해야 합니다.

## 순위와 표시 규칙

1. `best_streak` 내림차순 → 최고 기록 최초 달성 시각 오름차순 → 사용자 UUID 오름차순으로 정렬합니다. 완전히 같은 점수라도 화면 순서는 결정적이어야 합니다.
2. 초기 기본안은 인증 계정 중 공개 경기에서 1승 이상 확정한 사용자만 포함합니다. 개발 게스트·미정산 경기·향후 친선전은 제외합니다.
3. 상위 100명을 표시하고, 로그인한 사용자는 100위 밖이어도 본인 최고 기록·순위를 조회할 수 있습니다. 기록이 없으면 순위 없음과 첫 승리 안내를 표시합니다.
4. 승리 후 최고 기록이 바뀌면 정산 완료 뒤 재조회합니다. 현재 연승이 끊겨도 최고 기록 순위는 유지합니다.
5. 공개 정보는 순위·닉네임·최고 연승·필요한 달성 시각으로 제한합니다. 이메일·토큰·내부 세션 정보는 반환하지 않습니다.
6. 별도 시즌·지역·캐릭터 순위, 실시간 관전·유저 검색은 P1 이후입니다.
7. 계정 탈퇴·통계 무효 정정이 있으면 다음 조회에서 반영합니다. 점수는 이 브랜치에서 수정하지 않습니다.

## 추가 조회 계약 제안

- 공개 상위 목록과 인증된 본인 순위 조회를 구분합니다. 응답 예시는 `entries`, `myEntry`, `updatedAt`, `rankingRuleVersion`입니다.
- `entries`는 서버에서 정렬하고 최대 100개로 제한합니다. 본인 항목은 로그인 ID로 찾으며 요청의 임의 userId를 본인으로 취급하지 않습니다.
- 같은 응답의 목록·본인 순위는 같은 DB 조회 기준 시각 또는 트랜잭션 스냅샷을 사용합니다. 동시에 다른 경기가 정산돼도 서로 모순되지 않게 합니다.
- 캐시는 초기 최대 10초를 기본안으로 하고 F06 최고 기록 갱신·F01 탈퇴 시 무효화합니다. 화면에는 갱신 시각을 표시합니다. 설정은 실제 조회량에 따라 변경할 수 있습니다.
- 페이지 로딩·빈 목록·오류·갱신 중을 구분합니다. 마지막 성공 목록을 유지할 경우 오래된 상태임을 표시합니다.

## 수용 기준

| 시나리오                    | 기대 결과                                             |
| --------------------------- | ----------------------------------------------------- |
| 점수가 다른 세 사용자       | 최고 연승 내림차순                                    |
| 최고 연승이 같음            | 먼저 최초 달성한 사용자가 우선                        |
| 점수·달성 시각이 같음       | UUID로 순서 고정, 재조회해도 흔들리지 않음            |

| 새 최고 기록 정산·탈퇴      | 캐시 정책에 맞춰 갱신, 삭제 계정 정보 미노출          |
