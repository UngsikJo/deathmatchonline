# F07 — 재접속·장애 복구

- 브랜치: `feature/reconnection`
- 우선순위: P0
- 상태: 기본 자동 재접속 구현, 영구 결과 복원·장애 정리 미완료
- 기준: `bfe35d3`, [PRD](../PRD.md) 7·11절
- 선행 기능: F05, F06, [기능 목록](README.md)

## 목표와 현재 상태

짧은 통신 장애나 새로고침 후 같은 경기에 복귀하고, 복귀가 불가능하면 확정된 결과를 조회합니다. 반복적인 접속 종료로 시간을 멈추거나 불리한 패배를 취소할 수 없어야 합니다.

현재 Colyseus 재접속 좌석·누적 10초 유예, 연결 단절 중 이동 정지, sessionStorage 토큰과 복귀 시도가 있습니다. 서버가 종료되면 전투 메모리는 사라지며, 경기 결과 조회·참가 잠금 복구·인스턴스 생존 감시는 없습니다.

## 상태와 우선순위

1. 유예는 경기당 실제 연결 단절 누적 최대 10초입니다. 서버가 경과 시간을 계산하고 매번 접속할 때 예산을 새로 주지 않습니다.
2. 단절 중 전투와 제한 시간은 계속됩니다. 해당 사용자 이동 입력만 0으로 바꾸며 승인된 시전·투사체는 진행하고 공격받을 수 있습니다.
3. 체력 0 또는 제한 시간 결과가 유예 만료보다 먼저 확정되면 그 결과를 우선합니다. 결과 확정 뒤 연결 이벤트가 이를 덮어쓰지 않습니다.
4. 한쪽만 유예 내 복귀하지 못하면 해당 사용자 패배, 연결된 상대 승리입니다. 양쪽 모두 끊겼고 확정된 사망·시간 결과가 없으면 무효 처리합니다.
5. 전투 중 명시적 기권은 즉시 패배이며 재접속 유예를 제공하지 않습니다. 준비·카운트다운 이탈은 F05 취소 정책을 따릅니다.
6. 기존 좌석·세션과 재접속 토큰의 관계를 확인합니다. 재로그인한 다른 계정으로 경기 신원을 바꾸거나 타인 좌석에 들어갈 수 없습니다.
7. 복귀 시 체력·쿨다운·시전·남은 시간·마지막 처리 입력 순번을 서버 상태로 복원합니다. 끊긴 동안의 오래된 스킬 입력을 재발동하지 않습니다.
8. 경기당 60초의 결과 방 보관 여부와 무관하게 F06의 확정 경기 조회가 가능해야 합니다. 재접속 실패를 새 매칭으로 자동 전환하지 않습니다.

## 서버 장애와 잠금 복구

- 인스턴스 heartbeat와 참가 lease를 서버에서 갱신하고 정리 작업이 만료 여부를 확인합니다. 갱신 주기·유효 기간·정리 주기는 설정으로 두고 테스트에 기록합니다.
- 단순 heartbeat 지연만으로 살아 있는 전투를 무효화하지 않도록 유예·인스턴스 상태·DB 경기 상태를 함께 확인합니다.
- 커밋된 정산은 보존합니다. 결과를 영구 저장하지 못한 종료 인스턴스의 `active`·`finalizing` 경기는 트랜잭션으로 무효화하고 잠금을 해제합니다.
- 복구 작업을 중복 실행해도 결과가 같아야 하며, 이미 새 티켓으로 교체된 참가 잠금은 지우지 않습니다.
- MVP는 진행 전투 상태를 다른 서버에서 이어 실행하지 않습니다. 서버 장애 시 확정 결과 조회 또는 무효 안내가 범위입니다.

## 메시지·화면 계약 제안

클라이언트 연결 상태와 경기 상태를 분리합니다. `reconnecting`은 연결 상태이고 `finalizing`은 F06의 저장 상태입니다. 유예 만료·기권·서버 장애 무효를 구분한 사유와 본인 최근 경기 조회 정보를 전달합니다. 재접속 토큰은 성공 시 갱신하고 URL·로그·상대 스냅샷에 포함하지 않습니다.
