# 커밋 메시지 작성 규칙

이 저장소의 새 커밋은 **유형·코드 식별자 등 필요한 영문을 제외하고 제목과 본문을 한국어로 작성**합니다. 이미 원격에 공개한 커밋은 이 규칙을 맞추기 위해 재작성하지 않습니다.

## 기본 형식

```text
<유형>(<범위>): <한국어 제목>

<변경 이유와 필요한 상세 설명>

검증: <실제로 수행한 검사와 결과>
관련 이슈: #번호
```

- 유형은 아래 표의 영문 소문자를 사용합니다. 범위·본문·검증·이슈 줄은 필요한 경우에만 추가합니다.
- 유형과 제목 사이에는 콜론과 공백 하나를 둡니다. 범위가 없으면 `docs: 한국어 커밋 메시지 규칙 추가`처럼 씁니다.
- 제목은 한 줄, 72자 이내를 기준으로 합니다. 한국어는 글자 수로 계산하고 UTF-8 바이트 수로 세지 않습니다.
- 제목 끝에 마침표를 붙이지 않고 `추가`, `수정`, `정리`, `개선`, `제거` 등 실제 변경을 나타내는 말로 마칩니다.
- 한 커밋에는 하나의 목적을 담습니다. 제목만 읽어도 어떤 동작이나 문서가 바뀌었는지 알 수 있게 씁니다.
- 본문을 쓰면 제목 뒤에 빈 줄을 두고, 변경 이유·결과·주의할 영향 순으로 한국어로 설명합니다. 하지 않은 검증을 통과했다고 적지 않습니다.

## 유형

| 유형       | 사용 상황                         | 예시                                                |
| ---------- | --------------------------------- | --------------------------------------------------- |
| `feat`     | 사용자 기능·서버 기능 추가        | `feat(F06): 경기 결과와 연승 영구 정산 추가`        |
| `fix`      | 잘못된 동작 수정                  | `fix(F07): 재접속 유예 시간이 초기화되는 오류 수정` |
| `docs`     | 기획·명세·실행 안내·작업 일지     | `docs(F04): 스킬 판정 수용 기준 정리`               |
| `refactor` | 동작을 유지하는 코드 구조 개선    | `refactor(server): 경기 정산 저장소 분리`           |
| `test`     | 테스트 추가·수정                  | `test(F06): 중복 정산 방지 검증 추가`               |
| `perf`     | 측정 근거가 있는 성능 개선        | `perf(F09): 최고 연승 순위 조회 개선`               |
| `style`    | 실행 동작을 바꾸지 않는 코드 포맷 | `style(web): 들여쓰기와 줄바꿈 정리`                |
| `build`    | 빌드·패키징·의존성 변경           | `build(deps): Phaser 버전 갱신`                     |
| `ci`       | 자동 검사·배포 워크플로 변경      | `ci: 프로젝트 자동 검사 활성화`                     |
| `chore`    | 위 유형에 해당하지 않는 유지보수  | `chore: 개발용 임시 파일 제외 설정 추가`            |
| `revert`   | 기존 변경을 되돌리는 새 커밋      | `revert(F04): 결정타 피해량 변경 되돌리기`          |

화면 디자인·배치·색 변경은 코드 포맷용 `style`로 분류하지 않습니다. 기능 추가라면 `feat`, 잘못된 표시의 수정이라면 `fix`를 선택합니다. 기능 구현에 필요한 테스트·문서도 같은 목적이면 함께 커밋할 수 있습니다.

## 범위 선택

- 단일 기능 작업은 [기능 목록](features/README.md)의 `F01`~`F12`를 우선 사용합니다.
- 특정 계층이나 공통 설정 작업은 `web`, `server`, `shared`, `db`, `deps`, `release`처럼 실제 대상이 드러나는 식별자를 사용할 수 있습니다.
- 저장소 전체 문서·작업 일지 등 범위가 분명하면 괄호를 생략합니다.
- 범위를 과도하게 나열하지 않습니다. 서로 독립적인 기능이 섞이면 커밋을 나누고, 하나의 공통 변경이면 그 목적을 제목에 씁니다.

## 영문을 유지할 수 있는 경우

유형·범위·기능 ID, 코드의 함수·변수·타입명, 파일 경로, 브랜치명, 패키지명, 제품·기술 고유명, 명령어, 오류 코드와 자동 처리용 식별자는 원문을 유지합니다. 설명 문장과 일반 동사는 한국어로 씁니다.

| 권장                                                      | 피할 표현                    |
| --------------------------------------------------------- | ---------------------------- |
| `fix(F03): ArenaScene 포커스 상실 시 이동 정지 처리 수정` | `fix: update movement logic` |
| `docs: README에 서버 실행 방법 추가`                      | `docs: update README`        |
| `test(F07): 재접속 후 입력 중복 적용 검증 추가`           | `test: 테스트 업데이트`      |
| `feat(F08): 승리 후 자동 매칭 취소 기능 추가`             | `feat: 기능 작업 완료`       |

제목·본문에 비밀번호, 토큰, 사용자 이메일 등 민감한 값은 넣지 않습니다. 로그의 원문 오류를 인용해야 하면 비밀 값을 제거하고 필요한 코드만 사용합니다.

## 본문 예시

```text
fix(F07): 재접속 시 누적 유예 시간이 초기화되는 오류 수정

다시 연결할 때마다 새 유예 시간을 받던 처리를 수정합니다.
한 경기에서 끊긴 시간을 합산해 총 10초까지만 복귀를 허용합니다.

검증: npm run test:integration 통과
관련 이슈: #12
```

위 결과는 작성 형식 예시입니다. 실제 커밋에서는 해당 작업에서 수행한 검증 결과로 바꿉니다. 복잡한 변경의 여러 줄 본문은 임시 텍스트 파일에 작성한 뒤 `git commit --file <파일 경로>`로 전달할 수 있습니다.

호환되지 않는 메시지·API·DB 계약 변경은 제목의 유형/범위 뒤에 `!`를 붙이고 본문에 영향과 이행 방법을 적습니다. 자동 도구가 읽는 표식은 원문으로 유지합니다.

```text
feat(shared)!: 경기 결과 메시지에 저장 상태 추가

클라이언트와 서버를 같은 버전으로 배포해야 합니다.
기존 결과 응답의 처리 순서를 새 저장 상태에 맞춰 변경합니다.

BREAKING CHANGE: 이전 클라이언트는 새 경기 결과 형식을 처리할 수 없음
```

## 브랜치·PR·병합

- 커밋 메시지는 변경한 기능의 범위를 따르고, 브랜치는 기존 `feature/*` 이름을 유지합니다.
- PR 제목도 같은 한국어 제목 형식을 사용합니다. squash 병합 시 최종 커밋 제목·본문을 확인합니다.
- 병합·되돌리기 도구가 제목을 자동 생성하더라도 편집 가능한 제목은 한국어로 작성합니다. 예: `chore: 로비 UI 명세 브랜치 병합`.
- 기존 원격 이력의 영문 제목은 그대로 둡니다. 이 규칙 적용을 위해 강제 푸시하지 않습니다.
- 이 규칙은 작성 지침입니다. 현재 `commit-msg` 훅이나 원격 커밋 메시지 자동 검사는 설치하지 않았습니다.

## 로컬 작성 템플릿

저장소의 [커밋 메시지 템플릿](commit-template.txt)을 사용할 수 있습니다. 프로젝트 루트에서 다음 명령을 실행하면 이 저장소의 로컬 Git 설정에만 적용됩니다.

```sh
git config --local commit.template "$PWD/docs/commit-template.txt"
```

이후 `git commit`으로 편집기를 열면 안내가 표시됩니다. `git commit -m "docs: 커밋 작성 규칙 정리"`처럼 메시지를 직접 지정하는 경우에는 템플릿이 자동 삽입되지 않으므로 같은 규칙을 직접 적용합니다.
